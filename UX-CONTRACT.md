Language: th-TH; timezone: Asia/Bangkok; money: THB integer satang in storage, formatted at the UI boundary.

New project: no sibling workflows or inherited theme existed. This contract establishes shared owners. Per-page checklist: store (search/category/cart), login/register (validation/session), wallet (bank details/slip results/ledger), orders (settle/cancel/tracking), referrals (copy/link/QR), dashboard (real data/bar/donut), products/promotions/announcements (CRUD/empty/error), finance (income/expense/export), members/roles (least privilege/confirmation), settings (masked secrets/integration state), audit (read-only chain verification).

All mutations disable their submit control while pending; failures retain form values. Lists have bounded server pages. Committed search/page live in URL; sensitive form values never do. Cart persists only non-sensitive product IDs/quantities. Server is authoritative for stock, prices, discounts and all permissions.

Registration requires separate firstName (ชื่อหน้า), lastName (นามสกุล), phone, email and password. discoverySource (รู้จักเราจากที่ไหน) and lineId (Line ID Add) are optional text fields. Names accept Unicode and use given-name/family-name autocomplete. Telephone uses type tel and is normalized on the server by removing spaces, parentheses and hyphens; allow Thai 9–10 digit local numbers or +country numbers of 8–15 digits. This is format validation, not SMS verification. Keep the combined name for existing displays and orders. Additive migration leaves legacy names, credentials and balances unchanged, with empty profile columns. Profile contact/source data is available only to its owner and staff with members permission; do not include it in public referral statistics, bot context or audit details. The member list displays contact/source and searches phone/LINE ID as well as name/email.

Google authentication: server/google-auth.mjs owns authorization-code + S256 PKCE, random state, browser-bound HttpOnly SameSite=Lax 10-minute cookies and nonce. The fixed callback comes from server configuration, never Host/query/client input. POST start/complete require the configured Origin. Consume hashed state/browser attempts atomically before exchange. Google's official OAuth2Client verifies signatures, issuer, audience and expiry; additionally require the stored nonce, a bounded subject and verified valid email. Provider tokens/codes/secrets never enter client storage, audit or sessions. Identify returning members by linked Google subject, preserving role, balance and contact data. Disabled/expired-reset accounts cannot log in; active forced-reset members still go to /account and restricted APIs remain blocked. No automatic linking by matching email: require the existing local password, cap five failures per pending flow, and preserve the original member. New customers complete the shared profile schema (Google supplies verified immutable email), retain an optional active referral and receive role customer/balance 0. Their random unusable local hash has has_password=0; password login is disabled and account UI explains Google access. Reset-password sets has_password=1. Admin email changes unlink Google and revoke sessions; Google-only customers must get a password reset before changing email. Unique subject/user identity constraints and transactional completion prevent duplicate accounts or partial registrations. Migration 7 is additive and sets has_password=1 for legacy members. All cookies are Secure on the HTTPS origin, including behind the development tunnel. Missing optional credentials disables only Google; malformed configured credentials stop startup with generic diagnostics. The JSON lives in .secrets, excluded from Git/Docker/Vite serving, and is read only by the server. Auth cancellation, stale attempts and provider failures offer a clean restart without exposing provider error text.

Financial rules: wallet purchases debit atomically; deposit minimum accepts 0. Deposit orders reserve inventory and owe the balance; balance must be paid before shipping. Full-wallet payment is also supported. Referral commission uses the discounted total, with the configured percentage snapshotted at order creation in integer basis points, rounded down to satang. Credit only upon completed + fully paid order, within the completion transaction, once per order. Cancelled orders void pending commission. The user asked for a balanced policy and this choice was stated before implementation. Changes affect new orders only; the default 0% disables new commissions. Cancellation refunds precisely the amount actually paid, once, and restores inventory. A cancelled order releases its coupon use.

Appearance and campaigns: reusable ImageUpload and Carousel live in src/experience.tsx. PNG/JPEG are fully decoded and re-encoded; uploads max 5 MB, input 16–6000px and 24M pixels, favicon must be square and is normalized to 256px. Media blobs live in SQLite and are included in backups. Recommended sizes: banners 1600×600; announcements 1080×1350; promotions 1200×800; logo 640×240; favicon 256×256. Images keep containment rather than crop essential content.
Favicon PNG alpha, including semitransparent pixels, must survive upload/resizing. Preview uses a CSS checkerboard; upload status distinguishes real transparency from opaque images. JPEG and opaque PNG are accepted with an honest opaque status; do not imply that PNG conversion removes a white background. Media URLs are immutable, so replacement must create a new media ID and retain the previous asset.
Merchant payment QR: the owner supplied 2116.jpg on 2026-10-24, superseding the previous decision to wait for a store upload. The owner subsequently approved root QRcode.jpg; its decoded payload matches 2116.jpg and the installed crop. Retain the cropped image and record the confirmed source plus refreshed Branch verification in audit. A deterministic crop retains the original code and bank symbol on a white 1080×1440 canvas; decoding before and after must return identical payloads. Only settings-authorized staff may upload/select/remove paymentQr media. The server decodes a single static PromptPay phone/national-ID QR, validates TLV, currency/country, CRC and absence of preset amounts/tips. Fetch paginated GET /bank-accounts (Branch-scoped, never /all); require an exact configured bank/account plus a PROMPTPAY record matching the decoded identifier and both holder names. Reject unreadable, unsupported, mismatched or unregistered/unlinked QR and provider failures. Repeat the provider check when selecting a new QR for saving; guard concurrent receiving account/API key changes. Store a server-generated verification record, recipient hash and credential fingerprint. Legacy unverified images and stale bindings are hidden. Recipient/API key changes clear the previous image; unrelated changes preserve verified images. QR appears beside the receiving account when the card has at least 360px inner width, in a 180x180 frame. Server-decoded QR geometry projects only the original code pixels into this square, with a four-module white quiet zone, removing excess portrait-image whitespace without changing the original/download or payment payload; narrow cards stack it below the account. Click the image to open the shared Modal; the separate enlarge button is removed at the owner's request. Download and retry work on mobile. Matching registered records is not a bank inquiry proving which bank account a PromptPay alias routes to. Customers still check the recipient in their banking app; verified-slip matching remains authoritative for credits. QR upload/display never changes wallet balances.

Customer navigation: a customer logging in or visiting login while authenticated returns to /. Staff retain a validated internal next destination. Header profile is an accessible UserRound link and logout is an accessible LogOut button with pending/error feedback and revoked session.

Address book: server/addresses.mjs owns authenticated per-user CRUD with CSRF, up to 20 addresses. Require label, recipient, Thai phone and full postal address; coordinates are optional but paired and bounded. First address is primary; setting a new primary clears the previous one atomically; deleting a primary selects the oldest remaining address. A partial unique index prevents multiple defaults. Version checks reject stale edits/default changes/deletes. Audit records IDs and actions without address content. Account uses shared Form/Modal/Confirm. MapPicker in src/address-book.tsx serves both account and checkout, lazily loading src/address-map.tsx. Support click/drag, arrow-key panning + Enter to pin the center, manual coordinates and explicit geolocation with failure recovery. Map tiles retain attribution and browser caching, with no prefetch. Saved/default address can fill checkout once; late reloads must not overwrite edited shipping. Orders store a validated shipping/coordinate snapshot, independent of subsequent edits or deletion. Personal addresses never enter public settings or bot context.

Contact channels: shared/socials.json owns the LINE/Facebook/Telegram/TikTok/Instagram platform list and allowed HTTPS hosts. Settings permission controls URLs; empty hides a channel, credentials and other hosts are rejected. Shared SocialLinks displays local full-color SVGs and labelled new-tab links with noopener/noreferrer. BankLogo displays the original SCB logo for 014 and a neutral bank icon for an unknown bank.

Banner/announcement slides have scheduled visibility and numeric ordering (lower first). Default cycle 6s, configurable 3–30s, wrap around; pause on hover, keyboard focus, hidden document and reduced-motion. Manual previous/next/dots and pause are available. Announcements close for the current session and set of IDs/versions; future editions can appear again. The popup remains home-only. Back to top lives at bottom-left, appears after 250px scroll and respects reduced motion.

Promotions may require a member to collect the coupon before redemption. Claim is idempotent and does not reserve discount inventory. Expiry, minimum, global and per-user use limits are rechecked transactionally at checkout; a claim alone does not guarantee remaining availability. Legacy direct-code promotions stay usable without collecting.

Top-up fails closed until an exact receiving bank/account is configured. EasySlip must affirm matching account and amount, nonduplicate, THB and a recent timestamp. Unique bank+transaction reference, image digest and request id prevent duplicate wallet credits. No manual credit endpoint exists.

Roles: customer sees only own records; admin has all permissions; custom staff roles are explicitly assigned permissions. Last admin cannot be demoted/disabled. Permission change confirmation identifies the user. No self-promotion. Settings secrets stay server-only and encrypted at rest.

Customer management: src/member-management.tsx extends the existing MembersPage with shared Form/Field/Modal actions; server/member-management.mjs owns PUT /admin/members/:id/profile and POST /admin/members/:id/reset-password. Both require members AND member_edit, valid CSRF/origin, the operator's current password and a current member_version. The immutable customer role is the only allowed target; no staff/admin edits or resets through these endpoints. Member-view permission alone is read-only. Registration and profile edits share memberProfileSchema. Validate normalized Thai/international telephone, bounded names/source/LINE ID and unique lower-case email, rejecting privilege/balance fields. Successful profile edits revoke all customer sessions and increment version; role/status/password changes also increment version to invalidate stale dialogs. Orders, wallet balances, referral links and roles stay independent of profile editing.

Reset generates 18 random bytes encoded as a 24-character temporary password, hashes it with the existing salted scrypt owner, expires it in 24 hours, revokes sessions and marks must_change_password. Only the creation response contains plaintext with no-store; UI masks it by default, supports explicit reveal/copy, keeps it only in component memory and erases it by unmounting on close. No emails or LINE messages are sent. Lost results require a fresh explicit reset with current version. Rate-limit failed sensitive operator requests to 10 / 15 minutes per operator; successful operations do not consume that budget; rate-limit password changes with the existing authentication limiter. Audit only action, IDs, changed-field names and expiry; never credentials/contact values. Failed operator reauthentication is audited without submitted values. The reset response is not retrievable by a GET/list endpoint.

Temporary-password login is restricted server-side to me/public/health, public product/media reads, login, logout and password change; protected personal reads and mutations return PASSWORD_CHANGE_REQUIRED. Expired reset sessions are revoked. StoreLayout/Protected send the user to /account, which shows only password replacement and logout, without address book. Require current temporary password, a different new password of at least 12 characters, and matching confirmation. Clear the flag/expiry atomically, revoke sessions again and return to login. Generic authentication failures remain nondisclosing. Schema version 6 migration is additive/repeatable with version=1, reset flag=0 and null expiry for existing users.

External bot never has tools for financial operations or personal records. Signed LINE webhooks are processed by a durable inbox worker, event IDs are deduplicated, retry is bounded. Repeated failures are visible in audit and bot status.

Consignment: server/consignments.mjs owns membership, seller products, approval and fee settings; src/consignments.tsx owns customer /consignment and admin /admin/consignments using shared forms, dialogs, tables and URL tabs/pagination. Membership is separate from staff roles. The user confirmed seller-owned products and store-deducted fees. Approved members submit products with their own sanitized uploads; creates/edits unpublish for approval. Staff need consignments permission to approve members/products; only settings permission can change the global 0–100% fee in 0.01% increments, default zero. Disabling membership unpublishes products; self purchase is rejected. Snapshot each seller line's proportionally discounted base, fee basis points, fee and net in the order transaction. Allocate leftover discount satang by largest remainder with product-ID tie breaks; fee uses integer BigInt division, rounded down. Complete + fully paid settles the net once into the seller wallet in the same transaction; cancellation voids pending lines. Seller ledgers contain no buyer contact/address data. Referral commission remains an independent store expense. No bank withdrawal workflow is implied.

Reviews: server/reviews.mjs and src/reviews.tsx own product reviews and /admin/reviews. User confirmed completed, fully paid verified buyers only, one review per user/product with own edits. Require integer 1–5 stars using native keyboard-operable radios, a 1–2000 character comment, and at most five owned product-bound media IDs, including at most one video. Reject seller self reviews. Version stale edits/deletes/moderation fail with 409. Hidden review edits remain hidden. Public listings expose only first names; published media require visible attached reviews; pending/hidden media are owner/reviews-staff only. Moderator needs reviews permission and a reason. Attachments are privately staged, cleaned on cancellation and after 24 hours orphaned; uploads have per-user quotas and a global 500 MB ceiling. PNG/JPEG ≤5 MB are decoded/re-encoded; MP4/WebM ≤50 MB and ≤60 seconds are probed and transcoded by server/review-video.mjs using local FFmpeg/ffprobe, file-only protocols, bounded time/resolution/concurrency, stripped metadata, max25 MB normalized output. No unverified video pass-through. Serve controlled byte ranges for native playback, no autoplay; comments invite descriptions of video content. No claim of automatic captions. Existing media are deleted only on successful replacement/delete. Audit records actions/IDs/rating/count and moderation reasons, never attachment contents.
