Social browser return and disconnection (24 October 2026): OAuth starts in the current browser. Persist only a coarse browser kind with the expiring attempt, never the raw user agent. A valid, unexpired state arriving without its original flow cookie may open /auth/browser-return, but cannot link, log in, exchange a token, or consume the attempt until the original cookie is presented. Recovery carries only bounded provider/state/code-or-error and an allowlisted browser kind in a fragment, clears the fragment from history on mount, and permits only fixed same-origin callback URLs. Platform links require user activation; Safari wrong-browser recovery explicitly copies into the original Safari tab. Copy failure exposes a selectable temporary URL. Retry has a loop guard; expired/replayed/unknown proofs fail closed. Browser recognition is a routing hint, never authentication. Existing attempts default to generic same-browser behavior.

The existing LINE/Google button toggles between connect and disconnect. Disconnect is an own-account POST protected by Origin, CSRF, current password or a provider session fresher than ten minutes, and a current connection fingerprint. Reject stale dialogs, inaccessible providers masquerading as a remaining login, and removal of the last usable passwordless login. Commit identity removal, pending-link/attempt cancellation, other-session revocation and audit atomically; preserve the current session and all member, wallet, order and transaction data. Removing LINE stops new LINE slip funding through the existing binding check. This removes the store binding; it does not claim to revoke grants in the external provider account.

New project: no sibling workflows or inherited theme existed. This contract establishes shared owners. Per-page checklist: store (search/category/cart), login/register (validation/session), wallet (bank details/slip results/ledger), orders (settle/cancel/tracking), referrals (copy/link/QR), dashboard (real data/bar/donut), products/promotions/announcements (CRUD/empty/error), finance (income/expense/export), members/roles (least privilege/confirmation), settings (masked secrets/integration state), audit (read-only chain verification).

All mutations disable their submit control while pending; failures retain form values. Lists have bounded server pages. Committed search/page live in URL; sensitive form values never do. Cart persists only non-sensitive product IDs/quantities. Server is authoritative for stock, prices, discounts and all permissions.

Google authentication: server/google-auth.mjs owns authorization-code + S256 PKCE, random state, browser-bound HttpOnly SameSite=Lax 10-minute cookies and nonce. The fixed callback comes from server configuration, never Host/query/client input. POST start/complete require the configured Origin. Consume hashed state/browser attempts atomically before exchange. Google's official OAuth2Client verifies signatures, issuer, audience and expiry; additionally require the stored nonce, a bounded subject and verified valid email. Provider tokens/codes/secrets never enter client storage, audit or sessions. Identify returning members by linked Google subject, preserving role, balance and contact data. Disabled/expired-reset accounts cannot log in; active forced-reset members still go to /account and restricted APIs remain blocked. No automatic linking by matching email: require the existing local password, cap five failures per pending flow, and preserve the original member. New customers complete the shared profile schema (Google supplies verified immutable email), retain an optional active referral and receive role customer/balance 0. Their random unusable local hash has has_password=0; password login is disabled and account UI explains Google access. Reset-password sets has_password=1. Admin email changes unlink Google and revoke sessions; Google-only customers must get a password reset before changing email. Unique subject/user identity constraints and transactional completion prevent duplicate accounts or partial registrations. Migration 7 is additive and sets has_password=1 for legacy members. All cookies are Secure on the HTTPS origin, including behind the development tunnel. Missing optional credentials disables only Google; malformed configured credentials stop startup with generic diagnostics. The JSON lives in .secrets, excluded from Git/Docker/Vite serving, and is read only by the server. Auth cancellation, stale attempts and provider failures offer a clean restart without exposing provider error text.

Financial rules: wallet purchases debit atomically; deposit minimum accepts 0. Deposit orders reserve inventory and owe the balance; balance must be paid before shipping. Full-wallet payment is also supported. Referral commission uses the discounted total, with the configured percentage snapshotted at order creation in integer basis points, rounded down to satang. Credit only upon completed + fully paid order, within the completion transaction, once per order. Cancelled orders void pending commission. The user asked for a balanced policy and this choice was stated before implementation. Changes affect new orders only; the default 0% disables new commissions. Cancellation refunds precisely the amount actually paid, once, and restores inventory. A cancelled order releases its coupon use.
