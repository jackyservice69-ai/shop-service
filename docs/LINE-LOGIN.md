# LINE Login และเติมเงินผ่านแชท

ระบบเตรียมแล้ว แต่ยังไม่เปิด LINE Login/เติมเงินผ่าน LINE จริง เพราะเจ้าของร้านยังไม่มี LINE Login Channel ตามคำตอบวันที่ 24 ตุลาคม 2026 การทดสอบใช้ผู้ให้บริการจำลองและฐานข้อมูลแยก ไม่ส่งข้อความหรือเติมเงินจริง

## เปิดใช้งาน

1. เข้า [LINE Developers Console](https://developers.line.biz/console/) สร้าง **LINE Login Channel** แบบ Web app ภายใต้ **Provider เดียวกัน** กับ Messaging API ของ LINE ร้าน แล้วเชื่อม LINE Official Account กับ Login Channel เพื่อให้ user ID ระหว่าง Login และ Chatbot ตรงกัน
2. ตั้ง Callback URL ของ LINE Login เป็น `https://app.ca77group.org/api/auth/line/callback` และตั้งสถานะ Channel ให้พร้อมใช้งานตาม LINE Console
3. เจ้าของร้านเข้า **หลังบ้าน → ตั้งค่าระบบ → LINE Chatbot → LINE Login และผูกบัญชีสมาชิก** ใส่ **LINE Login Channel ID** และ **LINE Login Channel Secret** แล้วเปิด LINE Login ก่อนบันทึก เป็นคนละชุดกับ Channel Secret/Access Token ของ Messaging API Secret เก็บเข้ารหัสและแสดงเพียงสถานะว่าตั้งค่าแล้ว
4. สำหรับรับสลิป เปิด LINE Chatbot และเติมเงินจากสลิปใน LINE ตั้ง Webhook URL ของ Messaging API เป็น `https://app.ca77group.org/api/line/webhook` เปิด Use webhook และ webhook redelivery ใน LINE Console ตั้งบัญชีผู้รับและ EasySlip ให้บัญชีลงทะเบียน/เชื่อมกับ Branch แล้ว ใช้ worker หนึ่งชุดต่อฐานข้อมูล
5. ลูกค้าเข้าสู่เว็บ เปิด **บัญชีของฉัน → เชื่อมต่อบัญชี → เชื่อมต่อ LINE** อนุญาต LINE ของตน แล้วเพิ่มร้านเป็นเพื่อนและส่งรูปสลิปในแชทส่วนตัว รูป JPEG/PNG/WebP ไม่เกิน 4 MB ครั้งละรูป ระบบอ่านจำนวนเงินจากผลตรวจสลิป ไม่ใช้ข้อความหรือ AI ดูผลได้จากข้อความตอบกลับและประวัติ **เติมเงินผ่าน LINE** ในกระเป๋าเงิน หลังบ้านแสดงช่องทางและเลขเหตุการณ์ตามสิทธิ์การเงิน

## เชื่อมสมาชิกเดิม

สมาชิกเดิมเชื่อม Google และ LINE ภายหลังได้จากหน้าเดียวกัน โดยใช้เซสชันที่เข้าสู่ระบบอยู่และยืนยันบัญชีกับผู้ให้บริการ ไม่ถามรหัสผ่านเว็บไซต์ซ้ำ และไม่บังคับเข้าสู่ระบบใหม่ภายใน 10 นาทีสำหรับการเชื่อมต่อ (ปรับตามคำขอเจ้าของร้าน 25 ตุลาคม 2026) การเชื่อมไม่เปลี่ยนอีเมล บทบาท ยอดเงิน หรือคำสั่งซื้อ บัญชีผู้ให้บริการหนึ่งบัญชีเชื่อมกับสมาชิกได้คนเดียว ไม่ย้ายการเชื่อมของสมาชิกอื่น

สมาชิกใหม่ผ่าน LINE กรอกชื่อ/นามสกุล โทร อีเมล และตั้งรหัสผ่านเว็บไซต์ก่อนสร้างสมาชิก LINE ยืนยันตัวตน LINE ไม่ได้รับรองอีเมลที่ผู้ใช้พิมพ์ หากอีเมลมีสมาชิกแล้วต้องเข้าสู่บัญชีเดิมแล้วเชื่อม LINE ไม่รวมบัญชีอัตโนมัติและไม่สร้างกระเป๋าซ้ำ

## การตรวจสอบและกู้คืน

OAuth ใช้ authorization code, PKCE S256, nonce และ state ผูกเบราว์เซอร์ คุกกี้ HttpOnly Lax อายุ 10 นาที ตรวจ ID token ผ่าน LINE verify endpoint บนเซิร์ฟเวอร์ ตรวจ issuer/audience/nonce/อายุอีกครั้ง ไม่เก็บ access/refresh/ID token การเชื่อมใช้ CSRF และผูกกับเซสชันเริ่มต้นที่ยังไม่ถูกยกเลิก ไม่อาศัย Strict session cookie ข้ามเว็บไซต์ใน callback

รับสลิปเฉพาะผู้ส่งจาก webhook ที่ตรวจ HMAC raw body แล้ว และเป็นแชทส่วนตัวกับ LINE ที่ผูกบัญชีลูกค้าอยู่ก่อนส่งรูป ช่อง Line ID Add เป็นข้อมูลติดต่อ ไม่ใช่การยืนยันตัวตน ไม่รับเติมจากกลุ่ม/บัญชีปิดใช้งาน/ทีมงาน/บัญชีที่ต้องเปลี่ยนรหัสผ่าน จำกัด 6 รูปต่อนาทีต่อลูกค้า ต้องตรวจชื่อ/บัญชีผู้รับตรง เงินบาท อายุสลิปไม่เกิน 24 ชั่วโมง และยอดจากข้อมูล EasySlip สองตำแหน่งตรงกัน

LINE ไม่ส่ง matchAmount เพราะไม่มีจำนวนเงินที่ลูกค้ากรอก จึงตรวจ amountInSlip เทียบ rawSlip.amount.amount พร้อมขอบเขต 0.01–1,000,000 บาท ถ้ามี isAmountMatched=false จะปฏิเสธ หน้าเว็บยังต้องให้ EasySlip ยืนยัน isAmountMatched=true ตามเดิม

ทะเบียน bank+transRef และ hash รูปใช้ร่วมกับเว็บและหลังบ้าน บันทึก topup, ledger, funding receipt, LINE provenance, ข้อความผลลัพธ์ และ audit ใน transaction เดียว ถ้าตอบ LINE ล้มเหลวหลังเติมแล้ว การลองตอบซ้ำจะใช้ผลเดิมโดยไม่ตรวจสลิปหรือเติมซ้ำ สถานะส่งตอบล้มเหลวไม่ลบยอดที่บันทึกแล้ว เจ้าหน้าที่ตรวจเลขรายการในธุรกรรมกระเป๋าเงิน/เหตุการณ์บอทได้

ถ้า EasySlip ตรวจสลิปสำเร็จแต่การเชื่อมต่อขาดก่อนร้านได้รับผล ผู้ให้บริการอาจมองว่าใช้ซ้ำในครั้งถัดไป ระบบจะไม่เดายอดหรือเติมเอง ให้เจ้าหน้าที่ตรวจเงินเข้าจริงและใช้ขั้นตอนเติมหลังบ้านตามสิทธิ์ โดยใช้ธนาคารผู้โอน+transRef เดียวกันเพื่อกันยอดซ้ำ รูปสลิปไม่ส่งให้ ChatGPT และไม่เก็บในฐานข้อมูลบอท ล้าง payload พร้อม reply token หลังทำงานสำเร็จ/หมดโควตาลองใหม่ ประวัติการเงินและผลการเติมยังอยู่

## ส่งรูปบัญชีรับเงินเมื่อลูกค้าขอบัญชี

เปิด LINE Chatbot และตั้ง Messaging API Channel Secret / Access Token ในหลังบ้านตามเดิม ลูกค้าพิมพ์ “ขอบัญชี”, “ขอเลขบัญชี”, “ขอชื่อบัญชี”, “ขอ QR”, “ขอรูปคิวอาร์”, “โอนเงินที่ไหน” หรือ “bank details” บอทจะส่งข้อความแนะนำและภาพกรอบบัญชีรับเงิน ใช้ได้ก่อนผูก LINE เพราะเป็นข้อมูลร้านสาธารณะ ส่วนการส่งสลิปเพื่อเติมเงินยังต้องผูก LINE ก่อนตามเงื่อนไขเดิม

รูปจับจาก `BankDetailsPanel` เดียวกับหน้ากระเป๋าเงิน ผ่าน Chromium ในเครื่อง ไม่มี header, ยอดเงิน, ชื่อลูกค้า, ประวัติหรือปุ่มดาวน์โหลดติดไป ข้อมูลบัญชีอ่านจากหลังบ้าน QR ใช้เฉพาะภาพที่ผ่านการตรวจและยังตรงบัญชี/EasySlip key ปัจจุบัน ไม่ส่งคำขอบัญชีให้ OpenAI

เครื่องที่รัน API ต้อง `npm run build` และ `npm run setup:browser` ก่อนใช้งาน บน Linux ติดตั้ง system dependencies ด้วย `npx playwright install --with-deps chromium`; Dockerfile เตรียม Chromium ให้แล้ว ฟอนต์ Noto Sans Thai อยู่ใน `public/fonts` พร้อม SIL OFL จึงไม่ต้องเรียก Google Fonts ระหว่างจับภาพ เบราว์เซอร์ที่จับภาพใช้เซสชันใหม่และอนุญาตโหลดเฉพาะ origin ภายในเครื่อง

`APP_ORIGIN` ต้องเป็น HTTPS สาธารณะที่เข้าถึง API ได้ (ร้านนี้ใช้ `https://app.ca77group.org`) เพราะ LINE โหลดภาพจาก `/api/line/bank-card/<fingerprint>/original.png` และ `preview.png` แบบไม่ต้องล็อกอิน ภาพต้นฉบับกว้าง 1080px พรีวิวกว้าง 540px และตรวจขนาดไฟล์ก่อนส่ง หากตั้งค่าบัญชี/QR/สี/API key เปลี่ยน ระบบเลิกให้บริการ URL เดิมและสร้างภาพใหม่ในการขอครั้งต่อไป ภาพที่ส่งไปแล้วอาจอยู่ในแคชของ LINE หากจับภาพไม่ได้หรือใช้ HTTP ในเครื่อง บอทส่งข้อมูลบัญชีปัจจุบันเป็นข้อความพร้อมลิงก์กระเป๋าเงินแทน มี audit `bot.bank_card_failed` สำหรับตรวจการตอบสำรอง การขอบัญชีไม่เพิ่มยอดเงินหรือเรียกตรวจสลิป

## เบราว์เซอร์เดิมและการยกเลิกการเชื่อมต่อ

LINE และ Google เริ่มจากเบราว์เซอร์ที่ลูกค้าเลือก ระบบจำชนิด Chrome บน Android/iPhone, Samsung Internet หรือ Safari ไว้กับคำขออายุ 10 นาที ไม่บังคับเปลี่ยนเป็น Chrome ถ้าผลกลับมาที่อีกเบราว์เซอร์ จะมีหน้ากลับไปยืนยันในตัวเดิม สำหรับ Safari ที่ถูกส่งกลับผิดแอป ให้คัดลอกลิงก์ยืนยันไปวางใน Safari ที่เริ่มไว้ ส่วน Android อาจมีหน้าต่างเลือกแอปของระบบ การเปลี่ยนแอปไม่ยกเว้นคุกกี้/state/PKCE เดิม และไม่ใช้ชนิดเบราว์เซอร์เป็นหลักฐานยืนยันตัวตน

หน้า “บัญชีของฉัน” ใช้ปุ่มเดียวกันสลับ “เชื่อมต่อ” / “ยกเลิกการเชื่อมต่อ” ของแต่ละผู้ให้บริการ เฉพาะการยกเลิกเชื่อมต่อยังต้องยืนยันรหัสผ่านเดิม หรือมีเซสชันผู้ให้บริการที่ยังใหม่สำหรับบัญชีไม่มีรหัสผ่าน ห้ามยกเลิกช่องทางสุดท้ายที่ใช้งานได้ ระบบยกเลิกเซสชันอุปกรณ์อื่นและคำขอผูกที่ยังค้าง พร้อมบันทึก Audit หลังยกเลิก LINE จะส่งสลิปผ่านแชทเพื่อเติมเงินไม่ได้จนกว่าจะผูกใหม่ ยอดเงินและประวัติเดิมคงอยู่ การยกเลิกนี้เป็นการลบการผูกกับเว็บร้าน ไม่ได้ลบสมาชิกหรือบัญชี Google/LINE ของลูกค้า
