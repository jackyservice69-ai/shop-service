# 2026-10-26 release

Deploy the same reviewed commit to the existing Render API and Vercel frontend for iyawarin.com. No secret, data, environment-variable, domain or plan changes.

Included: smoother pastel contact buttons; beauty/gadget browse photographs; food quick category; approval notification bell; per-shop consignment fees; account/shop photos and service-area descriptions; category selection and 1–8 image galleries in consignor products and approval review.

SQLite moves additively to schema v13. Customer balances, transactions, existing bill fee snapshots and order history are retained. Before application startup, `cloud-start.mjs` runs `backupBeforeMigration` against the persistent database when its version is below 13. SQLite's online backup API includes committed WAL content. The snapshot switches to DELETE journal mode so it is a standalone database file and must pass `quick_check` before the application or LINE worker starts. Failure blocks startup. Missing databases remain subject to the existing required-database guard. Current schema databases skip this snapshot. Backups live under the database directory's `backups/`; they are not copied into Git, sent to Vercel or printed as data. This release snapshot does not replace off-service backups and retention.

Release order: final checks → commit/push main → confirm or trigger Render deploy from that commit → verify snapshot/startup and live API → deploy Vercel from the same commit → verify production aliases, routes, frontend assets and read-only API access.

Runtime verification must not create customer accounts, edit production settings, send LINE messages, upload media or execute wallet/order transactions. Test writes use isolated fixtures only. Record the exact commit and provider deploy IDs in the release result.
