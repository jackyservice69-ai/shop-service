# Per-shop consignment fees — local, 26 October 2026

In **หลังบ้าน → ตัวแทนฝากขาย → สมาชิกตัวแทน → จัดการร้าน**, the owner can enable “กำหนดค่าฝากขายเฉพาะร้านนี้” and enter 0–100% with up to two decimal places. Disabling the override restores inheritance from the current global rate. Zero is an explicit override, never a fallback signal. The list displays the effective percentage and whether it comes from the shop override or the global default; changing the global default refreshes inherited rows. Draft input survives checkbox toggles and validation failures.

The existing `settings` authorization controls fee changes, matching the global fee setting. A staff member with `consignments` permission may still moderate membership without changing fees; omitted fee values preserve the existing override. Explicit rate/reset attempts require owner settings permission. Members see their own effective rate/source in the seller portal and cannot set their own fees.

Schema v12 adds nullable `consignors.fee_bps` (0–10000 basis points). NULL inherits `consignmentFeePercent`. The additive migration leaves all existing shops inheriting the same global rate and preserves orders, wallet balances, notifications and existing `consignment_sales` snapshots.

`PUT /api/admin/consignments/:id` accepts optional `feePercent` as a number or null, alongside existing version/status/note. Values are validated server-side, saved as integer basis points, protected by current authorization/CSRF/Origin and the member version, and audited as `consignment.shop_fee_changed` with previous/new basis points. The entire operation rolls back if its audit write fails. The admin list includes `defaultFeePercent`; `/api/consignment` reports the authenticated seller's effective `feePercent`, `defaultFeePercent` and own membership override.

At order creation, each consigned product resolves its seller's override or the global default independently. Fees are calculated against the line's subtotal after the existing exact discount allocation, rounded down to integer satang, and stored with net amount/rate in `consignment_sales`. Mixed-shop bills may use different rates, including 0% and 100%. Later rate changes never rewrite old snapshots, including 0%-deposit reservations. Existing completion/payment gates, cancellations, self-purchase protection and exactly-once seller credit remain unchanged.

Verification: isolated API tests cover owner/staff/customer access, validation, stale versions, omitted values, zero, reset, mixed-shop discounted bills, immutable old snapshots, future rates, settlement, audit rollback and v12 file-database migration/reopen. Browser checks exercise custom/inherited rates, live global-default changes, blank-field validation, draft retention, seller visibility, mobile/desktop and Axe.
