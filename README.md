# หิ้วลี่ — Personal shopping service

เว็บ Fullstack ภาษาไทย: React + TypeScript + Express + SQLite (Node built-in SQLite) ข้อมูลเก็บถาวรใน `data/hiewly.sqlite` ไม่ใช้ยอดเงินจำลองในระบบหลัก

## เริ่มใช้งาน

ต้องมี Node.js 24 ขึ้นไป

```powershell
npm ci
npm run setup
# ติดตั้ง FFmpeg/ffprobe สำหรับอัปโหลดวิดีโอรีวิวบน Windows
npm run setup:video
# ติดตั้ง Chromium สำหรับจับภาพบัญชีร้านส่งใน LINE
npm run setup:browser
# เฉพาะเมื่อต้องการสินค้าตัวอย่างสำหรับทดสอบ
npm run seed:demo
npm run dev
```

- หน้าร้าน: http://127.0.0.1:5174
- หลังบ้าน: http://127.0.0.1:5174/admin
- บัญชีผู้ดูแลที่สร้างครั้งแรก: ดู `.local-admin.txt` (รหัสสุ่ม ไม่ถูก commit)
- API: http://127.0.0.1:3002

ไฟล์ `.env` ในเครื่องนี้ตั้งค่า EasySlip, บัญชีรับเงิน และ LINE จากข้อมูลที่เจ้าของร้านให้แล้ว ไม่ใส่ secret ลงหน้าเว็บหรือ source control เปลี่ยนรหัสผู้ดูแลได้ที่ “บัญชีของฉัน” หลังเข้าสู่ระบบ

`npm run setup` รันซ้ำได้โดยไม่รีเซ็ตรหัสผ่านหรือข้อมูลร้าน ตัวอย่างสินค้ามีประกาศกำกับ ต้องตรวจสอบ/แก้ไขราคา รูปภาพ จำนวน และต้นทุนให้เป็นสินค้าจริงก่อนเปิดร้าน

## สิ่งที่ทำได้

**ขอบัญชีผ่าน LINE**: เมื่อลูกค้าพิมพ์ “ขอบัญชี”, “ขอเลขบัญชี”, “ขอ QR” หรือ “โอนเงินที่ไหน” บอทส่งภาพเฉพาะกรอบบัญชีรับเงินจากหน้าเว็บ มีโลโก้ธนาคาร เลขบัญชี ชื่อผู้รับ และ QR ปัจจุบันที่ตรวจแล้ว ใช้ข้อมูลหลังบ้านโดยตรงและสร้างภาพใหม่เมื่อเปลี่ยนบัญชี/QR ใช้ได้เมื่อเปิด LINE Chatbot และตั้ง Messaging API/APP_ORIGIN เป็น HTTPS แล้ว หากจับภาพไม่ได้จะตอบข้อมูลบัญชีเป็นข้อความแทน ดู [วิธีตั้งค่า](docs/LINE-LOGIN.md)

**LINE Login / เชื่อม Google และ LINE ภายหลัง / เติมเงินจากแชท LINE**: สมาชิกเปิด **บัญชีของฉัน → เชื่อมต่อบัญชี** เชื่อมผู้ให้บริการเพื่อใช้บัญชีและกระเป๋าเงินเดิม เฉพาะ LINE ที่ผูกแล้วส่งสลิปในแชทส่วนตัวให้บอทตรวจและเติมยอดได้ มีประวัติ “เติมเงินผ่าน LINE” กันซ้ำร่วมกับเว็บ/หลังบ้าน ไม่ส่งสลิปให้ AI ขณะนี้เตรียมระบบและช่องตั้งค่าแล้ว ยังไม่เปิด LINE จริงเพราะรอเจ้าของสร้าง LINE Login Channel ดู [วิธีตั้งค่าและข้อจำกัด](docs/LINE-LOGIN.md)

**เติมเงินจากหลังบ้าน**: ไป **หลังบ้าน → ธุรกรรมกระเป๋าเงิน → เติมเงินให้ลูกค้า** ค้นหาและเลือกลูกค้า ระบุจำนวนเงิน ที่มา เลขอ้างอิงและเหตุผล ตรวจชื่อ/อีเมลกับยอดก่อน–หลัง แล้วใส่รหัสผ่านผู้ดำเนินการเพื่อยืนยัน เงินเข้าทันทีเมื่อบันทึกสำเร็จ รองรับรับโอนที่ตรวจเอง เงินสด และเครดิตชดเชย/ปรับเพิ่มยอด โดยแสดง “เติมเงินโดยผู้ดูแล” แยกจากสลิป EasySlip

เจ้าของร้านใช้ได้ทันที ผู้มีสิทธิ์ดูการเงินดูประวัติได้ หากต้องการให้ทีมงานเติมด้วย ให้เจ้าของเปิด **สิทธิ์การใช้งาน → แก้ไขบทบาท → เติมเงินกระเป๋าลูกค้าจากหลังบ้าน** ซึ่งต้องมีสิทธิ์ดูการเงินด้วย ทีมงานต้องเข้าสู่ระบบใหม่หลังเปลี่ยนสิทธิ์ ระบบไม่มอบสิทธิ์เติมเงินให้ทีมเดิมอัตโนมัติ

ประวัติค้นหา/กรองประเภท/แบ่งหน้าได้ มีเลขธุรกรรม ผู้ดำเนินการ ที่มา เหตุผล เลขอ้างอิง จำนวนเงิน และยอดก่อน–หลัง รายการบันทึกแล้วแก้หรือลบไม่ได้ กดหรือส่งซ้ำไม่เพิ่มยอดอีก สำหรับรับโอนต้องใส่ **รหัสธนาคารผู้โอน 3 หลัก + transRef ให้ตรงกับข้อมูลสลิป** เพื่อป้องกันโอนเดียวเติมซ้ำระหว่างหลังบ้านกับ EasySlip เงินสด/ชดเชยใช้เลขที่เอกสารไม่ซ้ำ การตรวจเงินจริงและกรอกเลขอ้างอิงเป็นหน้าที่ผู้ดำเนินการ รายการเติมเองไม่ได้รับการยืนยันจาก EasySlip

**ปักหมุดแผนที่**: ลูกค้าเปิดเมนู **ที่อยู่จัดส่ง** หรือ **บัญชีของฉัน → ที่อยู่จัดส่ง → เพิ่ม/แก้ไขที่อยู่ → ปักหมุดบนแผนที่** คลิกหรือลากหมุด ปักตรงกลาง หรือใช้ตำแหน่งปัจจุบัน แล้วกด “ใช้หมุดนี้” และบันทึกที่อยู่ รองรับหลายที่อยู่/ที่อยู่หลักและใช้ตอนสั่งซื้อ การใช้ตำแหน่งปัจจุบันต้องได้รับอนุญาตจากเบราว์เซอร์ หากไม่อนุญาตยังปักเองหรือกรอกพิกัดได้ ระบบไม่เรียกหาตำแหน่งเองเมื่อเปิดหน้า

**บทบาทและสิทธิ์ทีมงาน**: เตรียมบทบาทเจ้าของร้าน ลูกค้า ผู้จัดการร้าน พนักงานบริการลูกค้า/จัดส่ง ฝ่ายการเงิน และฝ่ายการตลาดแล้ว ที่ **หลังบ้าน → สิทธิ์การใช้งาน** เจ้าของร้านปรับบทบาททีมงานหรือสร้างบทบาทใหม่ได้ การเลือกสิทธิ์ทำรายการจะเลือกสิทธิ์ดูที่จำเป็นให้ด้วย และเมื่อเปลี่ยนสิทธิ์ ระบบจะออกจากระบบทุกอุปกรณ์ของสมาชิกในบทบาทนั้น

| บทบาทเริ่มต้น | สิทธิ์ |
|---|---|
| เจ้าของร้าน | ทุกส่วน รวมบัญชีรับเงิน QR API keys อัตราค่าคอม/ค่าฝากขาย และการมอบสิทธิ์ทีมงาน |
| ผู้จัดการร้าน | ภาพรวม สินค้า ดู/อัปเดตออร์เดอร์ ดูข้อมูลติดต่อสมาชิก ตัวแทนฝากขายและรีวิว |
| พนักงานบริการลูกค้า/จัดส่ง | ดูออร์เดอร์และข้อมูลจัดส่ง อัปเดตสถานะ/เลขพัสดุ ไม่มีสิทธิ์ยกเลิกคืนเงิน |
| ฝ่ายการเงิน | ดูรายรับ–รายจ่าย/ธุรกรรม บันทึกรายการ และส่งออก CSV; เติมกระเป๋าเงินได้เมื่อเจ้าของมอบสิทธิ์เพิ่มเท่านั้น |
| ฝ่ายการตลาด | โปรโมชั่น/คูปอง ประกาศ แบนเนอร์ สี/โลโก้/Favicon/ระยะเวลาสไลด์ ไม่มีสิทธิ์บัญชีรับเงินหรือค่าคอม |
| ลูกค้า | หน้าร้านและข้อมูลของตนเอง; ตัวแทนฝากขายเป็นสถานะเสริมที่ต้องอนุมัติ ไม่ได้รับสิทธิ์ทีมงาน |

วิธีเพิ่มทีมงาน: ให้แต่ละคนสมัครบัญชีของตนเองก่อน แล้วเจ้าของร้านเปิด **หลังบ้าน → สมาชิก → จัดการ → บทบาท** เลือกหน้าที่และยืนยัน ไม่ใช้บัญชีเจ้าของร้านร่วมกัน ระบบไม่ได้เลื่อนบทบาทลูกค้า/ทีมงานเดิมให้อัตโนมัติ และยังคงป้องกันการถอด/ระงับเจ้าของร้านคนสุดท้าย

แยกสิทธิ์ **ดูออร์เดอร์ / อัปเดต / ยกเลิกคืนเงิน**, **ดูการเงิน / บันทึก / ส่งออก**, **ดูสมาชิก / แก้ข้อมูล / รีเซ็ตรหัส** และ **ภาพลักษณ์ / แบนเนอร์ / ตั้งค่ารับเงินและ API** แล้ว การซ่อนปุ่มมีการตรวจสิทธิ์ฝั่ง API ด้วย เจ้าของร้านมอบสิทธิ์คืนเงินหรือรีเซ็ตรหัสให้บทบาทที่ไว้ใจได้เป็นรายสิทธิ์ ส่วนบัญชีรับเงิน/QR/API/อัตราค่าธรรมเนียมยังเป็นเจ้าของร้านเท่านั้น ผู้มีแค่สิทธิ์ดูสมาชิกไม่เห็นยอดกระเป๋าเงิน และผู้ดูออร์เดอร์ที่ไม่มีสิทธิ์สินค้า/การเงินไม่เห็นต้นทุนสินค้า

Migration 8 เพิ่มบทบาทเริ่มต้นครั้งเดียวและมี Audit โดยไม่เปลี่ยน role_id รหัสผ่าน ยอดเงิน หรือออร์เดอร์เดิม บทบาทเก่าที่เคยได้สิทธิ์กว้างจะไม่ได้รับสิทธิ์อัปเดตออร์เดอร์/คืนเงิน/รีเซ็ตรหัส/บันทึกหรือส่งออกบัญชีใหม่โดยอัตโนมัติ เจ้าของตรวจแล้วเลือกให้เอง สิทธิ์ settings เดิมของทีมงานเปลี่ยนเป็นภาพลักษณ์/แบนเนอร์และยกเลิกสิทธิ์รับเงิน/API เซสชันทีมงานที่ย้ายสิทธิ์ถูกเพิกถอน ส่วนบทบาทที่แก้ไขภายหลังไม่ถูกรีเซ็ตเมื่อเปิดโปรแกรมใหม่

**เข้าสู่ระบบด้วย Google**: มีปุ่มพร้อมโลโก้ Google ในหน้าสมัครและหน้าเข้าสู่ระบบ บัญชีใหม่ยืนยันอีเมลผ่าน Google แล้วเติมชื่อหน้า นามสกุล และเบอร์โทรก่อนเปิดใช้งาน ส่วนอีเมลที่มีสมาชิกอยู่แล้วต้องยืนยันรหัสผ่านเดิมก่อนเชื่อม Google เพื่อรักษาบัญชี กระเป๋าเงิน และสิทธิ์เดิม ลูกค้ากลับหน้าแรกหลังเข้าสู่ระบบ การเข้าสู่ระบบเดิมด้วยอีเมล/รหัสผ่านยังใช้ได้

ไฟล์ `Credentials.json` ที่เจ้าของให้ถูกย้ายเป็น `.secrets/google-oauth.json` ฝั่งเซิร์ฟเวอร์แล้ว จำกัดสิทธิ์อ่านไฟล์บน Windows ให้ผู้ใช้เครื่องนี้และ SYSTEM กันออกจาก Git/Docker build และบล็อกการอ่านผ่าน Vite ทั้ง URL ปกติและ `/@fs/` ไม่วางไฟล์นี้ใน `public`, `src` หรือ `dist` ไม่ใช้ตัวแปร `VITE_` เก็บ client secret เมื่อย้ายเครื่องให้ติดตั้งไฟล์แยกจาก source/image หรือ mount แบบ read-only แล้วตั้ง `GOOGLE_CREDENTIALS_FILE` เป็น path ของไฟล์นั้น

เครื่องนี้ตั้งค่าโดเมนตามที่เจ้าของระบุ:

```dotenv
APP_ORIGIN=https://app.ca77group.org
GOOGLE_CREDENTIALS_FILE=./.secrets/google-oauth.json
GOOGLE_REDIRECT_URI=https://app.ca77group.org/api/auth/google/callback
```

ค่า credentials file มี default ตามตัวอย่าง จึงไม่จำเป็นต้องเพิ่มบรรทัดนั้นใน `.env` ถ้าใช้ตำแหน่งนี้ ตรวจใน [Google Cloud Credentials](https://console.cloud.google.com/apis/credentials) ว่า OAuth client ประเภท Web application มี **Authorized redirect URIs** ตรงกับ `https://app.ca77group.org/api/auth/google/callback` ทุกตัวอักษร กำหนดชื่อแอป/ข้อมูลติดต่อใน Google Auth Platform และหากแอปยังเป็น Testing ให้เพิ่มบัญชีผู้ทดสอบก่อนใช้งาน รายละเอียด flow อ้างอิง [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect) ระบบนี้ใช้ server redirect flow จึงเก็บ client secret บนเซิร์ฟเวอร์เท่านั้น

หากทดสอบบน localhost ให้เปลี่ยน APP_ORIGIN และ callback เป็น origin เดียวกัน และลงทะเบียน callback นั้นใน Google Cloud ด้วย หลังแก้ `.env` หรือเปลี่ยนไฟล์ credentials ให้เริ่ม API ใหม่ บัญชีที่สร้างผ่าน Google เริ่มต้นไม่มีรหัสผ่านท้องถิ่น ผู้ดูแลใช้ระบบรีเซ็ตรหัสผ่านเดิมเพื่อเพิ่มทางเข้าแบบรหัสผ่านได้ การเปลี่ยนอีเมลลูกค้าจะยกเลิก Google เดิม; บัญชี Google อย่างเดียวต้องรีเซ็ตรหัสผ่านก่อนเปลี่ยนอีเมล การรีเซ็ตจะยังบังคับเปลี่ยนรหัสใหม่แม้ผู้ใช้กลับเข้าผ่าน Google

**แก้ไขลูกค้า / รีเซ็ตรหัสผ่าน**: ที่ **หลังบ้าน → สมาชิก** เลือก “แก้ไขข้อมูล” เพื่อแก้ชื่อหน้า นามสกุล อีเมล เบอร์โทร ช่องทางที่รู้จักร้าน และ LINE ID หรือเลือก “รีเซ็ตรหัสผ่าน” ทั้งสองรายการต้องยืนยันด้วยรหัสผ่านของผู้ดำเนินการและจะออกจากระบบทุกอุปกรณ์ของลูกค้า บัญชีเจ้าของร้านใช้ได้ทันที; ทีมงานต้องมี “ดูสมาชิก” พร้อม “แก้ไขข้อมูลลูกค้า” หรือ “รีเซ็ตรหัสผ่านลูกค้า” ตามงานที่ได้รับ การดำเนินการนี้ใช้ได้เฉพาะบทบาทลูกค้า ไม่เปลี่ยนยอดเงิน บทบาท หรือประวัติออร์เดอร์

การรีเซ็ตสร้างรหัสสุ่มชั่วคราวอายุ 24 ชั่วโมง แสดงแบบปิดบังพร้อมปุ่มแสดง/ซ่อนและคัดลอก จะแสดงเฉพาะครั้งที่สร้าง กรุณาตรวจสอบตัวตนลูกค้าก่อนส่งมอบผ่านช่องทางที่เหมาะสม ระบบไม่ได้ส่งข้อความให้ลูกค้าอัตโนมัติ ลูกค้าเข้าสู่ระบบด้วยรหัสนี้แล้วต้องตั้งรหัสส่วนตัวใหม่ก่อนเข้าถึงข้อมูลส่วนตัว กระเป๋าเงิน หรือคำสั่งซื้อ รหัสเดิมและเซสชันเดิมใช้ต่อไม่ได้ หากปิดหน้าต่างก่อนเก็บรหัส สามารถรีเซ็ตใหม่ได้; ระบบเก็บเฉพาะ hash ไม่สามารถเปิดดูรหัสเดิมย้อนหลัง การเปลี่ยนรหัสสำเร็จจะให้เข้าสู่ระบบอีกครั้ง

**ตัวแทนฝากขาย**: สมาชิกเปิดเมนู “ฝากขาย” เพื่อสมัคร หลังร้านอนุมัติจึงลงสินค้าของตนได้ สินค้าใหม่หรือการแก้ไขต้องผ่านการตรวจอีกครั้ง ที่ **หลังบ้าน → ตัวแทนฝากขาย** จัดการสมาชิก สินค้า และยอดขายได้ ผู้มีสิทธิ์ตั้งค่าระบบกำหนดค่าฝากขาย 0–100% (เริ่มต้น 0%) คิดจากยอดสินค้าหลังแบ่งส่วนลดตามสัดส่วน ล็อกอัตราในออร์เดอร์ และปัดค่าธรรมเนียมลงเป็นสตางค์ ยอดสุทธิเข้ากระเป๋าตัวแทนเมื่อออร์เดอร์สำเร็จและชำระครบเท่านั้น ไม่มีการจ่ายซ้ำเมื่อส่งคำขอซ้ำ ค่าคอมมิชชั่นแนะนำเพื่อนเป็นค่าใช้จ่ายร้านแยกต่างหาก ยอดนี้ใช้ซื้อสินค้าในระบบได้; ยังไม่มีระบบถอนเงินออกธนาคาร

**รีวิวสินค้า**: เปิดรายละเอียดสินค้าเพื่อดูคะแนนเฉลี่ยและรีวิว เฉพาะลูกค้าที่ซื้อและรับสินค้าสำเร็จพร้อมชำระครบเท่านั้นที่ให้ 1–5 ดาวและความคิดเห็นได้ หนึ่งรีวิวต่อสมาชิกต่อสินค้า แก้ไขหรือลบของตนได้ และห้ามรีวิวสินค้าที่ตนฝากขาย แนบรวมสูงสุด 5 ไฟล์: PNG/JPG/JPEG ไม่เกิน 5 MB ต่อรูป และ MP4/WebM ได้ 1 คลิป ไม่เกิน 50 MB / 60 วินาที ระบบตรวจไฟล์จริง ล้างข้อมูลประกอบรูป และแปลงวิดีโอเป็น MP4 ก่อนเผยแพร่ **หลังบ้าน → รีวิวสินค้า** ซ่อนหรือเผยแพร่พร้อมเหตุผลได้ การแก้ไขรีวิวที่ซ่อนจะยังไม่เผยแพร่อัตโนมัติ

เครื่อง Windows นี้ติดตั้ง FFmpeg 9.0.2/ffprobe ใน `tools/ffmpeg` แล้ว สคริปต์ `setup:video` ตรวจ SHA-256 ของชุดติดตั้งจาก Gyan ที่เชื่อมโยงในหน้า download ของ FFmpeg ก่อนแตกไฟล์ เครื่อง Linux ติดตั้ง FFmpeg/ffprobe รุ่นที่ยังได้รับอัปเดตผ่าน package manager; Dockerfile ติดตั้งให้ สามารถกำหนด `FFMPEG_PATH` และ `FFPROBE_PATH` เป็น absolute path ได้ หาก runtime ไม่พร้อม ระบบปฏิเสธวิดีโอแทนการเผยแพร่ไฟล์ที่ไม่ตรวจสอบ รูปรีวิวยังใช้งานได้ วิดีโอถูกจำกัดแปลงครั้งละหนึ่งงานต่อ process; ผู้ใช้อื่นจะได้รับข้อความให้ลองใหม่ สื่อรีวิวเก็บใน SQLite และรวมอยู่ในการสำรองข้อมูล

หน้าสมัครสมาชิกแยก **ชื่อหน้า / นามสกุล** และบังคับกรอก **เบอร์โทร** พร้อมช่องเสริม **รู้จักเราจากที่ไหน / Line ID Add** ข้อมูลบันทึกถาวรและแสดงในหลังบ้าน → สมาชิก ค้นหาได้ด้วยชื่อ อีเมล เบอร์โทร และ LINE ID สมาชิกเก่ายังใช้ชื่อ บัญชี และยอดเงินเดิมได้

| ส่วน | ความสามารถ |
|---|---|
| หน้าร้าน | ค้นหา หมวดหมู่ รายละเอียด ตะกร้า ราคาและสต็อกจากเซิร์ฟเวอร์ |
| สมาชิก | สมัคร เข้าสู่ระบบ ออกจากระบบ เปลี่ยนรหัสผ่าน ยกเลิกเซสชัน |
| กระเป๋าเงิน | เติมจากสลิป ยอดพร้อมใช้ ประวัติซื้อ/เติม/คืนเงิน |
| ชำระเงิน | จ่ายเต็ม หรือจองมัดจำเริ่ม 0% ชำระส่วนที่เหลือก่อนส่ง |
| คำสั่งซื้อ | สำรองสต็อก ยกเลิก คืนยอดจ่ายจริง ติดตามเลขพัสดุ |
| แนะนำเพื่อน | ลิงก์/QR, ค่าคอมต่อบิล, ประวัติยอดรอจ่าย/จ่ายแล้ว |
| หลังบ้าน | Dashboard กราฟแท่ง/โดนัท จากรายการจริง รวมรายจ่ายค่าคอม |
| สินค้า/โปรโมชั่น/ประกาศ | สร้าง แก้ไข ปิดใช้งาน รูปประกอบ คูปองเก็บสิทธิ์ และตรวจ version |
| บัญชีร้าน | รายรับอื่น/รายจ่าย, ledger ลูกค้า, CSV ป้องกันสูตรแฝง |
| สิทธิ์ | ผู้ดูแล ลูกค้า และบทบาททีมกำหนดเอง ตรวจฝั่งเซิร์ฟเวอร์ |
| LINE | ตั้งค่า token/secret ข้อความตอบพื้นฐาน webhook ลงลายเซ็น คิวถาวร |
| ChatGPT | รองรับ OpenAI Responses API เปิดในหลังบ้านหลังใส่ API key |
| Audit | บันทึกผู้ดำเนินการ เหตุการณ์ เวลา และตรวจ hash chain |

การปิดขาย/ปิดโปรโมชั่น/ปิดประกาศใช้สถานะ active เพื่อเก็บประวัติอ้างอิง ไม่มีการลบธุรกรรมเงินออกจากฐานข้อมูล

## สี ภาพลักษณ์ และแคมเปญ

- **หลังบ้าน → สีและภาพลักษณ์**: สี 6 ค่า `primary`, `ink`, `muted`, `background`, `surface`, `positive`, ชุดพาสเทลชมพู–ฟ้า/พีช/มิ้นต์, โลโก้, Favicon, เวลาเปลี่ยนสไลด์ และ % ค่าคอมมิชชั่น
- **หลังบ้าน → แบนเนอร์**: หลายภาพ เลขลำดับน้อยแสดงก่อน วันเริ่ม/สิ้นสุด ลิงก์ในร้าน และปิดแสดงได้
- **หลังบ้าน → ประกาศ**: หลายประกาศพร้อมรูป/ข้อความ จัดลำดับ สไลด์วนใน popup หน้าแรก มีปุ่มหยุด ก่อนหน้า/ถัดไป และจำการปิดตาม IDs/versions ใน session
- **หลังบ้าน → โปรโมชั่น**: รูป ชื่อ รายละเอียด โค้ดส่วนลด และตัวเลือก “ต้องเก็บคูปองก่อนใช้ส่วนลด”
- **หน้าร้าน → โปรโมชั่น / คูปอง**: สมาชิกเก็บคูปองแล้วกดใช้ในตะกร้า ระบบคำนวณและตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ โค้ดเดิมที่ไม่บังคับเก็บยังใช้ได้เหมือนเดิม
- ปุ่มลูกศรกลับด้านบนอยู่มุมซ้ายล่างฝั่งลูกค้า ปรากฏเมื่อเลื่อนเกิน 250px

| ภาพ | ขนาดแนะนำ |
|---|---|
| แบนเนอร์ | 1600 × 600 px |
| Popup ประกาศ | 1080 × 1350 px |
| โปรโมชั่น | 1200 × 800 px |
| โลโก้ | 640 × 240 px |
| Favicon | 256 × 256 px (ต้องเป็นสี่เหลี่ยมจัตุรัส) |
| QR รับเงินของร้าน | 1080 × 1440 px (ภาพชัดเจน ไม่ตัดขอบ QR) |

ทุกประเภทรับ `.png`, `.jpeg`, `.jpg` สูงสุด 5 MB ต่อรูป รูปถูก decode/re-encode เพื่อตรวจไฟล์จริงและลบ metadata ไม่รับ SVG/GIF ภาพตั้งแต่ 16–6000px, ไม่เกิน 24M pixels; ภาพใหญ่ถูกย่อให้ไม่เกิน 2400px และ Favicon แปลงเป็น PNG 256px เสมอ ภาพเก็บใน SQLite จึงอยู่ในไฟล์สำรองด้วย พื้นที่รวมเริ่มต้น 250 MB และสูงสุด 60 รูป/ชั่วโมง/ผู้ใช้ เมื่อเต็มระบบจะปฏิเสธการอัปโหลดและต้องให้ผู้ดูแลจัดการพื้นที่

สีมีผลกับหน้าลูกค้าและตัวอย่างในหลังบ้าน ตัวอักษรบน primary เลือกดำ/ขาวตาม contrast อัตโนมัติ เจ้าของร้านควรเลือก ink/muted/positive ที่อ่านชัดบน surface/background ปรับ gradient/แสงตามสีร้าน ทุกหน้าของระบบไม่มี box-shadow และใช้ outline แสดงโฟกัสคีย์บอร์ด

Favicon ที่ไม่มีกรอบพื้นหลังควรเป็น **PNG โปร่งใส** ระบบรักษา alpha เมื่อย่อเป็น 256×256 px และแสดงลายตารางในพรีวิว พร้อมบอกหลังอัปโหลดว่ามีส่วนโปร่งใสหรือพื้นหลังทึบ JPG/JPEG ไม่รองรับความโปร่งใส และการแปลงไฟล์ที่มีพื้นขาวเป็น PNG ไม่ได้ลบพื้นขาวให้อัตโนมัติ

**QR รับเงิน:** หลังบ้าน → ตั้งค่าระบบ → ร้านค้าและการชำระเงิน → QR รับเงินของร้าน อัปโหลดรูปที่รับเงินเข้าบัญชีด้านบนแล้วกดบันทึก ลูกค้าเห็น QR ในหน้ากระเป๋าเงินเมื่อระบบเติมเงินพร้อมใช้งาน เปิดรูปใหญ่และบันทึกรูปลงเครื่องได้ หากเปลี่ยนผู้รับ/เลขบัญชี ระบบจะซ่อน QR เก่าและให้เพิ่มรูปใหม่ การสแกน QR ไม่ได้เพิ่มยอดทันที ยังต้องโอนและแนบสลิปที่ตรวจสอบผ่านเช่นเดิม

สไลด์เริ่มต้น 6 วินาที ตั้งได้ 3–30 วินาที มีปุ่มเปลี่ยนภาพ/หยุด และหยุดเมื่อ hover, focus, ซ่อนแท็บ หรือเปิด reduced motion

## ค่าคอมมิชชั่นแนะนำเพื่อน

ตั้ง % ได้ที่ **สีและภาพลักษณ์ → สไลด์และค่าคอมมิชชั่น** ค่าเริ่มต้น **0%** เพื่อไม่สร้างภาระจ่ายจนกว่าร้านจะเลือกอัตราเอง รองรับทศนิยม 2 ตำแหน่ง ตั้งได้ 0–100%

นโยบายแบบสมดุล: คิดจากยอดบิลหลังหักส่วนลด ล็อกอัตราและผู้แนะนำตอนสร้างคำสั่งซื้อ ปัดลงเป็นสตางค์ และจ่ายเข้ากระเป๋าผู้แนะนำเมื่อชำระครบและออร์เดอร์ `completed` เท่านั้น การเปลี่ยน % มีผลเฉพาะบิลใหม่ ไม่มีจ่ายย้อนหลังให้บิลเดิมหรือบิลยกเลิก และไม่มีค่าคอมจากการเติมกระเป๋าเฉย ๆ

ตัวอย่าง: บิล 1,000 บาท หักส่วนลด 100 บาท เหลือ 900 บาท อัตรา 5% ได้ค่าคอม 45 บาท เมื่อออร์เดอร์สำเร็จ เครดิตใช้ซื้อสินค้าในร้านได้ ระบบนี้ยังไม่มีถอนเงินออกธนาคาร

ดูประวัติได้ที่ **ชวนเพื่อน** สำหรับลูกค้า และ **หลังบ้าน → ค่าคอมมิชชั่น** สำหรับทีมที่มีสิทธิ์ finance ค่าคอมจ่ายพร้อม transaction ปิดออร์เดอร์ มี unique reference ใน ledger ป้องกันจ่ายซ้ำ และแสดงเป็นรายจ่ายใน dashboard

## กฎเงินและสต็อก

เงินทุกจำนวนเก็บเป็นจำนวนเต็มหน่วยสตางค์ สั่งซื้อและชำระใช้ transaction พร้อม `BEGIN IMMEDIATE` เพื่อให้ตัดยอด สร้าง ledger และลดสต็อกสำเร็จร่วมกันหรือย้อนกลับทั้งหมด

ยอดใบเสนอราคามี fingerprint ถ้าราคา ส่วนลด หรือมัดจำเปลี่ยนระหว่างตรวจยอดกับยืนยัน จะปฏิเสธและให้ยืนยันยอดใหม่ รหัส idempotency ป้องกันคำขอซ้ำ ไม่ใช้ราคาจาก localStorage มาคิดเงิน

มัดจำ 0% = สร้างคำสั่งซื้อและสำรองสต็อกโดยไม่ตัดเงิน สถานะ `reserved` ต้องชำระครบจึงไป `paid → processing → shipped → completed` ได้ เลขพัสดุจำเป็นก่อนจัดส่ง การยกเลิกก่อนจัดส่งคืนสต็อกและเฉพาะยอดที่จ่ายจริง เพียงครั้งเดียว ยังไม่มีหมดอายุการจองอัตโนมัติ เจ้าของร้านยกเลิกการจองที่ค้างได้จากหลังบ้าน

เงินเติมกระเป๋าเป็นยอดที่ร้านถือแทนลูกค้า แยกจากรายรับที่ชำระคำสั่งซื้อ ต้นทุนสินค้าต่อหน่วยเก็บเป็นข้อมูลอ้างอิง ไม่ถูกบันทึกเป็นรายจ่ายอัตโนมัติ ให้บันทึกรายจ่ายเมื่อจ่ายจริง เพื่อไม่ให้นับเงินซ้ำ

## EasySlip

ใช้ `POST https://api.easyslip.com/v2/verify/bank` พร้อม `matchAccount=true`, `matchAmount`, `checkDuplicate=true` ตรวจชนิดไฟล์จริงและขนาดไม่เกิน 4 MB แล้วตรวจคำตอบฝั่งเซิร์ฟเวอร์:

- `success=true`, `isDuplicate=false`, `isAmountMatched=true`
- ยอดทั้ง `amountInSlip` และ raw slip ตรงกับจำนวนเงินที่แจ้ง
- บัญชี ธนาคาร และชื่อผู้รับที่จับคู่ตรงกับบัญชีร้าน
- สกุลเงิน THB ประเทศ TH เวลาไม่เกิน 24 ชั่วโมง และไม่เกินเวลาปัจจุบัน 5 นาที
- transaction reference + ธนาคารผู้ส่ง และ image SHA-256 ต้องไม่เคยใช้ในร้าน

ไม่เก็บรูปสลิปดิบ คงไว้เฉพาะ digest, ยอด, reference และ audit หาก upstream ล่ม/โควต้าหมด/ไม่จับคู่ จะไม่เพิ่มเงิน ต้องลงทะเบียนบัญชีรับเงินและเชื่อมโยง Branch ใน EasySlip ด้วย มีปุ่มตรวจการเชื่อมต่อในหลังบ้าน

QR รับเงินของร้านตั้งค่าได้ที่ **หลังบ้าน → ตั้งค่าระบบ → QR รับเงินของร้าน** รองรับ PNG/JPEG ไม่เกิน 5 MB แนะนำ 1080×1440 px ระบบอ่าน QR และตรวจ CRC/สกุลเงิน/ผู้รับ อนุญาตพร้อมเพย์แบบไม่ระบุยอดเงิน โดยทั้งบัญชีธนาคารและบัญชี PROMPTPAY ที่เลขและชื่อผู้รับตรงต้องอยู่ใน Branch ของ API key เดียวกัน ([เอกสาร EasySlip](https://document.easyslip.com/th/v2/bank-accounts/list)) ตรวจซ้ำก่อนบันทึกภาพใหม่ และซ่อน QR เดิมเมื่อเปลี่ยนบัญชีหรือ API key คลิกรูปเพื่อขยายหรือบันทึกรูปได้

รูปที่เจ้าของร้านส่งใหม่ `2116.jpg` ถูกตัดกรอบเป็น `assets/payments/shop-qr-1080x1440.png` และตรวจว่าถอดรหัสได้ข้อมูลเดิม ติดตั้งในฐานข้อมูลร้านหลังตรวจรายการใน Branch จริงแล้ว เจ้าของร้านยืนยันไฟล์ `QRcode.jpg` ภายหลัง และตรวจแล้วว่ารหัสตรงกับรูปที่ติดตั้ง จึงคงรูปตัดกรอบเดิมพร้อมบันทึกการยืนยันแหล่งที่มาใน audit การจับคู่ข้อมูลที่ลงทะเบียนไม่ใช่บริการสอบถามธนาคารว่าหมายเลขพร้อมเพย์ผูกกับบัญชีใด ลูกค้าต้องตรวจผู้รับในแอปธนาคารก่อนโอน และการเพิ่มยอดยังต้องผ่านการตรวจสลิป

ลูกค้าจัดการที่อยู่ได้ที่ **บัญชีของฉัน → ที่อยู่จัดส่ง** เพิ่มได้ 20 รายการ เลือกที่อยู่หลักและปักหมุด/กรอกพิกัด/ใช้ตำแหน่งปัจจุบัน ที่อยู่หลักเติมใน checkout อัตโนมัติและเปลี่ยนเป็นที่อยู่อื่นได้ ออร์เดอร์เก็บสำเนาที่อยู่และพิกัด ณ วันที่สั่ง การแก้หรือลบที่อยู่จึงไม่เปลี่ยนออร์เดอร์เดิม แผนที่ใช้ Leaflet กับ OpenStreetMap และโหลดเฉพาะตอนเปิด การใช้ตำแหน่งปัจจุบันต้องได้รับอนุญาตจากเบราว์เซอร์และใช้ HTTPS หรือ localhost

ตั้งลิงก์ LINE, Facebook, Telegram, TikTok, Instagram ได้ที่ **ตั้งค่าระบบ → ช่องทางติดต่อร้าน** ลิงก์ที่กรอกจะแสดงโลโก้สีที่ท้ายหน้าร้าน เว้นว่างเพื่อซ่อน ลูกค้าล็อกอินแล้วจะกลับหน้าแรก และมีไอคอนโปรไฟล์/ออกจากระบบที่ส่วนหัว

## LINE และ ChatGPT

1. ตั้ง `APP_ORIGIN` เป็นโดเมน HTTPS จริงของร้าน
2. ตั้ง Webhook URL ใน LINE Developers เป็น `https://your-domain/api/line/webhook`, เปิด Use webhook
3. เปิด “บอทตอบข้อความ” ในหลังบ้าน แล้วกด Verify จาก LINE Developers
4. หากยังไม่มี OpenAI API key บอทตอบข้อความพื้นฐานได้
5. ถ้าต้องการ AI ให้ใส่ OpenAI API key และชื่อโมเดลที่บัญชีเข้าถึงได้ แล้วเปิด AI

ตรวจ HMAC-SHA256 จาก raw request ก่อนแปลง JSON, deduplicate webhookEventId และใช้ durable inbox worker ลองได้สูงสุด 3 ครั้ง การตอบสำเร็จล้างข้อความและ reply token จากคิว บริการ AI ใช้ `store:false`, ไม่มี tools, ส่งเฉพาะข้อมูลสินค้าสาธารณะ ไม่มีสิทธิ์อ่านบัญชีลูกค้าหรือทำธุรกรรม

การลองซ้ำ LINE ใช้ reply token เดิมซึ่ง LINE ใช้ได้ครั้งเดียว การรับประกัน exactly-once ข้ามฐานข้อมูลกับบริการภายนอกทำไม่ได้ คิวและสถานะผิดพลาดช่วยตรวจสอบกรณี timeout หลังบริการรับคำขอแล้ว

## ใช้งานจริง / สำรองข้อมูล

```powershell
npm run build
$env:NODE_ENV='production'
# ตั้ง APP_ORIGIN=https://your-domain ใน .env ก่อน
npm start
```

ให้ reverse proxy HTTPS เช่น Caddy/Nginx ส่งไป `127.0.0.1:3002` ตัวอย่าง `Caddyfile.example` ตัวเซิร์ฟเวอร์ production ให้บริการ frontend จาก `dist` ด้วย ไม่ใช้ Vite dev server ตั้ง `TRUST_PROXY=1` เฉพาะเมื่อมี proxy ที่เชื่อถือได้หนึ่งชั้น อย่าเปิดพอร์ต API สู่สาธารณะโดยตรง

สำรอง SQLite ด้วย `npm run backup` สคริปต์ใช้ SQLite online backup API; เก็บ `.env` / `SETTINGS_ENCRYPTION_KEY` ในที่ปลอดภัยแยกจากฐานข้อมูล หาก key หายจะถอดรหัส secrets ที่ตั้งผ่านหลังบ้านไม่ได้ Restore โดยหยุดแอปก่อนแล้วแทนที่ไฟล์ฐานข้อมูลจาก snapshot และใช้ encryption key เดิม

SQLite เหมาะกับร้านเดียวและแอปหนึ่ง instance บนดิสก์ถาวร หากต้องการหลาย instance ให้ย้าย transaction/ledger ไป PostgreSQL ก่อนเพิ่ม scale

## ขอบเขตความปลอดภัย

ใช้ scrypt พร้อม salt, opaque session token ที่เก็บ hash, cookie HttpOnly/SameSite และ Secure ใน production, CSRF token, origin checks, rate limiting, Zod validation, prepared SQL, Helmet/CSP, สิทธิ์บนเซิร์ฟเวอร์, secrets AES-256-GCM และ audit/ledger ที่มี trigger กันแก้/ลบ

hash chain ตรวจพบการแก้แถวทั่วไปได้ แต่ผู้ครอบครองไฟล์ DB และเครื่องยังสามารถแก้ทั้ง chain ได้ ควรสำรอง head hash ออกไปยังระบบอื่นถ้าต้องการหลักฐานต้านผู้ดูแลเครื่อง ไม่มีการอ้างว่าปลอดภัยสมบูรณ์หรือผ่าน security audit ภายนอก ยังไม่รวม email verification, forgotten-password email, 2FA, withdrawal และ payment gateway/card payments
